## ТЗ-1: Умный детектор аномалий (Smart Defect Analysis)

### 1. Цель
Автоматически анализировать остатки оксидов (defect) и давать вероятностные гипотезы о причинах аномалий, помогая пользователю понять проблемы с данными или алгоритмом.

### 2. Функциональные требования

#### 2.1. Правила детекции
| Паттерн остатков | Гипотеза | Уверенность |
|---|---|---|
| `CaO > 2%` + `SO₃ > 1%` | Присутствует гипс/ангидрит, не учтённый в схеме | Высокая |
| `Сумма < 95%` | Потеря летучих (LOI) или ошибка лаборатории | Средняя |
| `Сумма > 103%` | Ошибка нормализации или переучёт | Высокая |
| `Fe₂O₃ + FeO > 25%` | Железистая порода, возможна ошибка в Fe³⁺/Fe²⁺ | Средняя |
| `P₂O₅ > 2%` + `CaO defect` | Апатит не полностью учтён | Высокая |
| `defect > 5%` по одному оксиду | Критическая проблема — требуется ручной анализ | Критическая |
| `CO₂ > 5%` + `CaO defect` | Карбонаты не полностью распределены | Средняя |

#### 2.2. Формат вывода
```python
@dataclass(frozen=True)
class AnomalyHypothesis:
    severity: Literal["info", "warning", "critical"]
    pattern: str              # "high_ca_so3"
    message: str              # "Возможно, присутствует гипс..."
    confidence: float         # 0.0 - 1.0
    suggested_action: str     # "Проверьте исходные данные"
    affected_oxides: list[str]
```

#### 2.3. Интеграция
- Вызывается автоматически после `Calculator.calculate()`
- Результаты добавляются в `CalculationResult.anomalies: list[AnomalyHypothesis]`
- Отображаются на `ResultsPage` цветными иконками (🟢🟡🔴)

### 3. Архитектура
```
src/core/anomaly_detector.py      # Правила и логика
src/core/models.py                # + AnomalyHypothesis
src/gui/widgets/anomaly_badge.py  # UI компонент
```

### 4. API
```python
class AnomalyDetector:
    def __init__(self, rules_path: Optional[Path] = None): ...
    def analyze(self, result: CalculationResult) -> list[AnomalyHypothesis]: ...
    def analyze_batch(self, results: list[CalculationResult]) -> dict[str, list[AnomalyHypothesis]]: ...
    def add_rule(self, rule: AnomalyRule): ...
```

### 5. Критерии приёмки
- [ ] Детектируется ≥80% типовых аномалий из тестовых данных
- [ ] Не даёт ложных срабатываний на корректных образцах (БK-1, T-O2)
- [ ] Правила редактируемы через JSON
- [ ] Время анализа < 1 мс на образец

**Оценка:** 2 дня

## ТЗ-2: Смарт-тегизация в БД

### 1. Цель
Автоматически присваивать образцам скрытые теги на основе геохимических признаков для быстрого поиска и фильтрации.

### 2. Функциональные требования

#### 2.1. Типы тегов
| Категория | Примеры тегов | Условие |
|---|---|---|
| Геохимия | `high_alumina`, `carbonate_rich`, `iron_rich` | Пороги по оксидам |
| Тип породы | `type_1_dominant`, `type_3_dominant` | По `rock_type` |
| Минералы | `chlorite_rich`, `quartz_poor` | По вес.% минералов |
| Качество | `high_defect`, `low_sum` | По defect и сумме |
| Пользовательские | любые | Ручное добавление |

#### 2.2. Механизм
- Теги вычисляются **автоматически** при сохранении в БД
- Хранятся в таблицах `tags`, `sample_tags` (уже есть в ТЗ)
- Поддерживаются пользовательские правила (JSON)

### 3. Архитектура
```

```

### 4. API
```python

    def compute_tags(self, result: CalculationResult) -> list[str]: ...
    def add_rule(self, name: str, condition: Callable[[CalculationResult], bool]): ...
```

## ТЗ-5: Режим объяснения (Educational Mode)

### 1. Цель
Простым языком объяснять, почему алгоритм выбрал конкретный путь ветвления и какой физико-химический смысл имеют коэффициенты.

### 2. Функциональные требования

#### 2.1. Источники данных
- `DebugTrace` (уже есть) — пошаговая трассировка
- `AdaptiveCoefficients` — значения k1-k4
- `RockType` — выбранный тип породы

#### 2.2. Формат объяснения
Генерируется текстовое описание на русском:
```
Образец: БК-1
Тип породы: Type 3 (переходный к глинистым породам)
Причина выбора: Al₂O₃ недостаточно для Type 4, но MgO позволяет
                учесть хлорит через адаптивные коэффициенты.

Коэффициенты хлорита:
  k1 = 1.43 — доля Mg, идущая в хлорит
  k2 = 3.01 — доля Fe²⁺ в хлорите
  k3 = 1.47 — доля Al в хлорите
  k4 = 2.63 — доля Si в хлорите
Значение F = 0.696 означает, что ~70% железа в форме Fe³⁺.

Ключевые шаги расчёта:
  1. Переведено в формульные единицы (ф.е.)
  2. Вычтен апатит (P₂O₅ → CaO, F)
  3. Определён тип породы по соотношению Al-Na-K-Mg
  4. Распределены полевые шпаты (Ab, An, Or)
  5. Рассчитан хлорит по адаптивным коэффициентам
  ...
```

#### 2.3. Уровни детализации
- **Краткий** (1 абзац) — для быстрого обзора
- **Стандартный** (5-10 пунктов) — для понимания логики
- **Подробный** (полный trace с комментариями) — для отладки

### 3. Архитектура
```
src/core/explainer.py              # Генератор объяснений
src/gui/widgets/explanation_panel.py  # UI панель
data/explanations_ru.json          # Шаблоны текстов
```

### 4. API
```python

    def explain(self, result: CalculationResult) -> str: ...
    def explain_step(self, trace: DebugTraceCollector, step: int) -> str: ...
```

### 5. UI
- Боковая панель в `ResultsPage` (скрываемая)
- Всплывающие подсказки на коэффициентах k1-k4
- Кнопка «Объяснить расчёт» для выбранного образца

## ТЗ-6: Сравнительный дашборд «До/После»

### 1. Цель
Визуально сравнивать два расчёта (версии алгоритма, лаборатории, партии) с автоматической статистикой.

### 2. Функциональные требования

#### 2.1. Источники сравнения
- Два файла результатов (Excel)
- Два расчёта из БД (разные версии алгоритма)
- Один файл vs ручные данные

#### 2.2. Статистика
| Метрика | Описание |
|---|---|
| MAE | Средняя абсолютная ошибка |
| RMSE | Среднеквадратичная ошибка |
| R² | Коэффициент детерминации |
| Max Δ | Максимальное расхождение |
| N(Δ > 0.5%) | Количество минералов с расхождением > 0.5% |

#### 2.3. Визуализация
- **Таблица**: образец × минерал × значение1 × значение2 × Δ × Δ%
- **Bland-Altman plot**: разность vs среднее
- **Heatmap расхождений**: подсветка ячеек с Δ > порога
- **Гистограмма распределения Δ**

#### 2.4. Цветовое кодирование
- 🟢 Δ < 0.1% — отлично
- 🟡 0.1% ≤ Δ < 0.5% — приемлемо
- 🔴 Δ ≥ 0.5% — требует анализа

### 3. Архитектура
```
src/core/comparator.py                  # Сравнение результатов
src/gui/pages/compare_page.py           # Расширение существующей
src/gui/widgets/bland_altman_chart.py   # Новая диаграмма
```

### 4. API
```python
@dataclass(frozen=True)
class ComparisonResult:
    sample_name: str
    mineral: str
    value_a: float
    value_b: float
    delta: float
    delta_percent: float

class Comparator:
    def compare(
        self,
        results_a: list[CalculationResult],
        results_b: list[CalculationResult],
        key: Literal["name", "order"] = "name"
    ) -> ComparisonReport: ...

@dataclass(frozen=True)
class ComparisonReport:
    rows: list[ComparisonResult]
    statistics: dict[str, float]  # MAE, RMSE, R², ...
    outliers: list[ComparisonResult]  # Δ > threshold
```

### 5. UI
- Расширение `ComparePage` (уже есть в ТЗ)
- Выбор источников (два dropdown)
- Переключатель ключа (по имени / по порядку)
- Экспорт отчёта сравнения (PDF/Excel)

### 6. Критерии приёмки
- [ ] Сравнение 100 образцов × 34 минерала < 100 мс
- [ ] Статистика корректна (проверка на синтетических данных)
- [ ] Bland-Altman plot корректно строится
- [ ] Экспорт отчёта работает во всех форматах

## ТЗ-8: Песочница чувствительности (Sensitivity Sandbox)

### 1. Цель
Интерактивно изменять значения оксидов и в реальном времени видеть, как перераспределяются минералы, не запуская полный пересчёт.

### 2. Функциональные требования

#### 2.1. Интерфейс
- Выбор образца из списка
- Слайдеры для каждого оксида (диапазон: ±50% от исходного)
- Мгновенное обновление таблицы минералов
- График «дельта» (исходный vs текущий)

#### 2.2. Режимы
- **Один оксид**: изменяем один, остальные фиксированы
- **Несколько оксидов**: изменяем несколько одновременно
- **Сценарии**: предустановленные («+1% Fe₂O₃», «-2% CaO»)

#### 2.3. Ограничения
- Сумма оксидов автоматически нормализуется к 100%
- Предупреждение, если сумма вне диапазона [98, 102]
- Отключена запись в БД (режим «песочницы»)

### 3. Архитектура
```
src/gui/pages/sandbox_page.py           # Новая страница
src/gui/widgets/oxide_slider.py         # Кастомный слайдер
src/core/sensitivity.py                 # Быстрый пересчёт
```

### 4. API

### 5. UI

- Левая панель: слайдеры оксидов
- Центральная панель: таблица минералов (обновляется мгновенно)
- Правая панель: график дельт
- Горячие клавиши: `Ctrl+Z` — отмена, `R` — сброс

### 6. Производительность
- Пересчёт одного образца < 50 мс
- Обновление UI < 100 мс
- Использовать кэширование промежуточных результатов

### 7. Критерии приёмки
- [ ] Слайдер обновляет таблицу мгновенно (< 100 мс)

```json
    {"action": "export_pdf", "params": {"template": "standard"}}
  ],
  "hotkey": "Ctrl+Shift+R"
}
```

#### 2.3. Режимы
- **Запись**: пользователь выполняет действия, они записываются
- **Воспроизведение**: запуск макроса
- **Редактирование**: правка JSON вручную
- **Параметры**: переменные (`%LAST_FOLDER%`, `%DATE%`, `%SAMPLE_COUNT%`)

### 3. Архитектура
```
src/automation/macro_engine.py          # Движок макросов
src/automation/macro_recorder.py        # Запись действий
src/automation/actions.py               # Реестр действий
data/macros/                            # Папка с макросами
```

### 4. API
```python
class MacroEngine:
    def __init__(self, macros_dir: Path = ...): ...
    def load(self, name: str) -> Macro: ...
    def execute(self, macro: Macro, context: dict = None) -> None: ...
    def list_macros(self) -> list[Macro]: ...

class MacroRecorder:
    def start_recording(self) -> None: ...
    def record_action(self, action: str, params: dict) -> None: ...
    def stop_recording(self) -> Macro: ...
    def save(self, macro: Macro, path: Path) -> None: ...

@dataclass
class Macro:
    name: str
    description: str
    steps: list[dict]
    hotkey: Optional[str] = None
```

### 5. UI
- Меню «Макросы» в главном окне
- Диалог «Записать макрос» (красная кнопка REC)
- Диалог «Редактор макросов» (JSON с подсветкой)
- Панель «Быстрые действия» с кнопками макросов
- Настройка горячих клавиш

### 6. Безопасность
- Макросы выполняются в sandbox (ограниченный набор действий)
- Нет доступа к `eval()` или произвольному Python-коду
- Предупреждение перед выполнением макроса из недоверенного источника

### 7. Критерии приёмки
- [ ] Запись и воспроизведение базовых сценариев работает
- [ ] Горячие клавиши назначаются и работают
- [ ] Переменные (`%LAST_FOLDER%`) подставляются корректно
- [ ] Ошибка в одном шаге не ломает весь макрос (graceful fail)
- [ ] JSON-макросы валидируются при загрузке

**Оценка:** 5 дней

## 4. Расширение через плагины

### 4.1. Плагиновая система для алгоритмов
**Суть:** Возможность подключать альтернативные алгоритмы расчёта без изменения ядра.

**Функционал:**
- Интерфейс `AlgorithmPlugin`:
  ```python
  class AlgorithmPlugin(ABC):
      @abstractmethod
      def calculate(self, composition: OxideComposition) -> MineralComposition: ...
      @abstractmethod
      def get_name(self) -> str: ...
  ```
- Загрузка плагинов из папки `plugins/algorithms/`
- Выбор алгоритма в настройках (MINLITH, CIPW, пользовательский)
- Сравнение результатов разных алгоритмов

**Примеры плагинов:**
- CIPW norm (классическая норма)
- Norm calculation by Verma
- Пользовательский алгоритм для специфических пород

**Архитектура:**
```
plugins/
├── algorithms/
│   ├── cipw_norm.py
│   └── custom_norm.py
└── plugin_loader.py
```
