# EXCEL_VERSION_00 — Обзор оригинального MINLITH (карта, переменные, аудит)

**Дата:** 2026-09-09
**Источник:** `Ispravlenny_MINLITH1_2010.xlsm` (формулы+VBA)
**Связанные файлы:** `src/core/excel_port/data/*.json` (извлечённые данные)

---

## 1. Назначение документа

Это первый документ серии `EXCEL_VERSION_*.md`. Он даёт карту оригинального
алгоритма MINLITH: из каких листов, формул и именованных диапазонов он состоит.
Последующие документы (`01_stage0`, `02_types_1_2`, `03_types_3_5`,
`04_stageVI`, `05_output`, `06_rounding`, `07_vba_flow`) детализируют каждый блок.

Серия пишется, чтобы:
1. Зафиксировать, **как именно** считает оригинал (со всеми округлениями).
2. Служить основой для чистой Python-реализации `clean_engine` (без округлений).

## 2. Архитектура оригинала (3 слоя)

```
Входные оксиды (вес.%)
      │
      ▼
┌─────────────────────────────┐
│  ЛИСТ «Нач+Type 3»          │   подготовка (строки 1-42),
│  (типы 3-5)                 │   типы 3, 4, 5 (44-556)
└─────────────────────────────┘
      │  VBA переносит блоки A1:F19 и значения ячеек
      ▼
┌─────────────────────────────┐
│  ЛИСТ «Нач+Type 12»         │   стадия 0 (1-42),
│  (типы 1-2 + стадия VI)     │   типы 1, 2 (44-283),
│                             │   стадия VI (92-140),
│                             │   вес.% и нормировка (143-171),
│                             │   итог образца (287)
└─────────────────────────────┘
      │
      ▼
  minerals / defect (листы вывода)
```

**Ключевые факты:**

- **Вся арифметика** — в формулах ячеек этих двух листов.
- **Именованные диапазоны** (~76) — это «переменные» алгоритма.
- **VBA** (231 Sub) — поток управления: копирует значения ячеек-кандидатов в
  именованные диапазоны, выбирает ветки по булевым флагам, переносит блоки
  между листами. Сам VBA арифметику НЕ считает.
- **Межлистовых ссылок в формулах нет** — листы связаны только через VBA.

## 3. Листы книги

| Лист | Роль |
|------|------|
| `Guide` | инструкция пользователя |
| `ИСХ ДАННЫЕ` | вход: оксиды образца (колонка A — имя, B — вес.%) |

| `minerals` | вывод: минералы в вес.% (заполняет макрос) |
| `Нач+Type 3` | расчётный лист типов 3-5 |
| `Нач+Type 12` | расчётный лист типов 1-2 + стадия VI + вес.% |

## 4. Аудит формул (извлечено из .xlsm)

### 4.1 Лист «Нач+Type 12» — 418 формул

| Функция | Кол-во |
|---------|-------:|
| ROUND | 135 |
| IF | 34 |
| SUM | 12 |
| AND | 6 |
| COUNTA | 1 |

Ячеек с ROUND — 133. Межлистовых ссылок — 0.

### 4.2 Лист «Нач+Type 3» — 513 формул

| Функция | Кол-во |
|---------|-------:|
| IF | 77 |
| ROUND | 51 |
| AND | 38 |
| OR | 1 |

Ячеек с ROUND — 49. Межлистовых ссылок — 0.

### 4.3 Выводы аудита

- Язык формул прост: арифметика, `ROUND`, `IF`, `AND`, `OR`, `SUM`, `COUNTA`.
  Никаких `VLOOKUP`, `MIN/MAX` и т.п.
- Округление — на каждом шаге (`ROUND(...,0)`, `ROUND(...,2)`, `ROUND(...,3)`).
- Ссылки — на именованные диапазоны и соседние ячейки (A1 и R1C1 смешаны).

### 4.4 Идентичность .xlsx и .xlsm

Формулы в `MINLITH1.xlsx` (без макроса) и `Ispravlenny_MINLITH1_2010.xlsm`
(с макросом) **идентичны** (418/418 и 513/513), отличие — одна ячейка `I283`
(`COUNTA(A290:A440)` vs `COUNTA(A290:A601)`), счётчик, не влияет на расчёт.

## 6. Классификация типа породы (флаги F20-F25 листа «Нач+Type 3»)

| Ячейка | Условие (текст в B) | Имя | Переход |
|--------|---------------------|-----|---------|
| F20 | Al < Na° + K° | Тип 1 | aType_1 |
| F21 | Al <= 1.2Na° + K° | Тип 1 | aType_1 |
| F22 | Al <= 1.2Na° + 3.25K° | Тип 2 | aType_2 |
| F24 | Al <= 1.2Na°+3.25K°+(Mg°-0.5K°·k3)/k1 | Тип 3 | aType_3 |
| F25 | Al <= 5Na°+3.25K°+(Mg°-0.5K°-2Na°)·k3/k1 | Тип 4 | aType_4 |
| (иначе) | — | Тип 5 | aType_5 |

VBA-диспетчер `v_1..v_14` последовательно проверяет F20→F25 и вызывает
соответствующий `aType_N`.
