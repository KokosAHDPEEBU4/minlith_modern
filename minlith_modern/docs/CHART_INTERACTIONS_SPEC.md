## 1. Термины

- **Плитка** (`_ChartTile`) — виджет одной диаграммы в сетке.
- **Сетка** (`MultiChartView`) — контейнер плиток на страницах «Диаграммы» и «Вывод».
- **Рендерер** — класс, строящий matplotlib Figure для одного типа диаграммы.
- **Взаимодействие** — действие пользователя: колесо мыши, кнопки, drag, клик, hover.
- **Спецификация взаимодействий** — неизменяемый датакласс, описывающий, какие взаимодействия поддерживает тип диаграммы и как они работают.
- **Категория диаграммы** — декартовы оси, декартовы с категориальной осью, равноаспектные/тройные, круговые, тепловые, полярный частный случай.

## 2. Цели рефакторинга

1. Устранить двойной зум при активной лупе matplotlib.
2. Заменить «зум вслепую» на модель **возможностей по типу диаграммы**: каждый рендерер явно объявляет, какие взаимодействия поддерживает.
3. Дать круговым/тройным диаграммам осмысленные взаимодействия вместо бесполезного масштабирования пределов.
4. Реализовать сценарий синхронизированного зума между диаграммами.
5. Групповые операции: «сбросить все», «приблизить все».
6. Сохранить текущие гарантии: экспорт текущего вида, освобождение фигур, offscreen-тестируемость.

**Нецели:** изменение рендеринга диаграмм; изменение Plotly-диаграмм (экспортируются в статичный HTML, вне зоны ответственности сетки); производительная оптимизация отрисовки.

## 4. Архитектура после рефакторинга

### 4.1. Новый модуль спецификаций

Создать `src/gui/widgets/chart_interactions.py` (имя фиксировано):

- **Перечисление категорий** диаграмм (пять значений + полярный частный случай).
- **Датакласс спецификации** с полями:
  `zoom_xy`, `zoom_x`, `zoom_y`, `pan`, `rect_zoom`, `resettable`, `hover_info`, `click_action`, `sync_group`, `default_limits`, `min_range_width` (лимит зума по абсолютной ширине диапазона). Все поля — со значениями по умолчанию; спецификация неизменяемая.
- **Реестр**: отображение «тип диаграммы → спецификация». Единственное место, знающее категорию каждого типа. Плитка и сетка запрашивают спецификацию только из реестра.

**Главный архитектурный критерий приёмки:** плитка не содержит ветвлений по типу диаграммы — никаких `if chart_type == "pie"` в `chart_grid.py`. Вся типозависимость — только в реестре спецификаций.

### 4.2. Декларация возможностей (формат спецификации)

Плитка при установке фигуры читает спецификацию и подключает только разрешённые обработчики. Кнопки без поддержки **скрываются** (не дизейблятся — меньше визуального шума). Для pie остаётся только «По умолчанию».

В спецификацию добавляется поле допустимого шага **не добавляется**: шаг — параметр сетки/приложения. Спецификация описывает *что можно*, настройки — *как быстро*.

### 4.3. Разделение ответственности

| Слой | Отвечает за |
|---|---|
| Рендерер / реестр | Тип диаграммы, шкалы осей, декларация возможностей, `default_limits`, действие сброса |
| Плитка | Привязку/отвязку событий (mpl_connect/mpl_disconnect), якорь, разбор модификаторов, кнопки |
| Сетка | Групповые операции, синхронизацию, шаг зума (получает от конфига), защиту от циклов |
| Тулбар matplotlib | Только неконфликтующие инструменты |

### 4.4. Отключение встроенного scroll-зума

Встроенный scroll-зум тулбара **отключается полностью** для всех типов. Колесо обрабатывает только собственный обработчик плитки. Это устраняет сдвоенный зум и делает поведение единообразным независимо от активного инструмента тулбара. Тулбар matplotlib **урезается**: `home` → наш сброс, `save` → наш экспорт; zoom/pan дизейблятся для типов без поддержки.

## 5. Категории диаграмм

- **A** — декартовы, обе оси числовые;
- **B** — декартовы с категориальной осью;
- **C** — равноаспектные/тройные/классификационные;
- **D** — круговые;
- **E** — тепловые/матричные;
- **B♦** — полярный частный случай (radar).

Специальные типы (dendrogram, PCA, defect) маппятся на ближайшую категорию через **таблицу в реестре**, не через условия в плитке.

**Нюансы матрицы**

- **Radar:** полярные оси не используют `set_xlim/set_ylim` — зум через радиальные пределы (`set_rlim`), якорь фиксирован в центре (`r=0` всегда видим); пан отключён.

- **Dendrogram:** зум по Y (расстояние) уместен, по X (метки) — бесполезен. Категория B.
- **PCA biplot:** двойная семантика (точки и стрелки загрузок). Зум XY допустим; стрелки обязаны масштабироваться согласованно — проверить рендерер приёмочным тестом.
- **Parallel coordinates:** rect-zoom запрещён (выделенная область имеет разный смысл на каждой вертикальной оси); зум/пан по Y — единые для всех осей.

Объединение ключей — только по явному решению после ручной проверки.
6. **Hover «опц.»** — желательно, но не блокирует этап; базовый статусбар тулбара с координатами считается достаточным.

## 8. Спецификация по взаимодействиям

### 8.1. Колесо мыши

- Вверх — приблизить, вниз — отдалить.
- **Шаг — настраиваемый**, дефолт **×1.2** (значение из настроек приложения, не из плитки; см. §10).
- Якорь — точка под курсором; вне области данных (`event.inaxes is None`) — игнор.
- **Модификаторы (решено):**
  - `Ctrl+колесо` — зум по оси X;
  - `Ctrl+Shift+колесо` — зум по оси Y;
  - `Shift+колесо` — панорамирование по X.
  Разбор модификаторов изолирован в одном приватном методе, возвращающем единый enum-результат (`zoom_xy / zoom_x / zoom_y / pan_x / none`).
- Лог-шкалы: пересчёт в log10 с сохранением якоря; защита `<= 0` — переход на линейную ветку (существующая логика переносится в чистый модуль).
- Категориальные оси: зум запрещён (номинальные метки не масштабируются).
- Равноаспектные (C): единый фактор на обе оси.

### 8.2. Кнопки плитки

- Набор «Отдалить», «Приблизить», «По умолчанию» сохраняется; неподдерживаемые действия скрываются.
- Центральный якорь кнопок (зум вокруг центра) — как сейчас.
- Добавляется кнопка **«Приблизить по области»** — свой режим rect-zoom (единый вход), дублирующий зум тулбара. Тулбарные zoom/pan для типов без поддержки дизейблятся.

### 8.3. Панорамирование

- «Рука» — только для A, B (по числовой оси), C (равный аспект), E; для D выключено.
- Для C: пан обязан сохранять равенство аспекта (`ax.set_aspect('equal', adjustable='datalim')` после изменения пределов), логика — в плитке.

### 8.4. Сброс «По умолчанию»

- Декартовы: текущая логика `relim() + autoscale_view()`.
- Pie/равноаспектные: восстановление исходных пределов **и аспекта** (защита от сплюснутого круга).
- Типы с фиксированными пределами по смыслу (TAS, QAPF и пр.): сброс возвращает **декларированные рендерером** пределы (`default_limits`), а не autoscale по данным.
- Сброс остаётся локальным + добавляется групповой сброс в шапке сетки.

### 8.5. Hover и клик (категория D и не только)

- Pie: hover → подсказка «Название — значение (процент)»; клик → **explode** (выдвигание среза на фиксированную долю радиуса, повторный клик — возврат).
- Реализация через `motion_notify_event` и `button_press_event` канваса; hit-testing среза — по `event.inaxes.patches` с `contains`.
- **Offscreen:** API должен позволять вызывать обработчик с синтетическим событием (текущая практика с колесом).
- Hover не требует расширения `ChartData`: работа с существующими патчами фигуры.
- Для остальных категорий hover обязателен только при флаге в спецификации; статусбар тулбара — достаточный минимум.

### 8.6. Групповые операции сетки

- «Приблизить все» / «Отдалить все» — только для поддержанных плиток; круговые пропускаются молча.
- «Сбросить все» — все плитки.
- Групповые операции: мутация всех пределов → **одна** отрисовка затронутых канвасов (бюджет §12).

## 9. Синхронизированный зум

### 9.1. Модель

- Группы — по ключу `sync_group` из спецификации (для Harker — ось X + тип шкалы).
- Переключатель «Синхронизировать зум» в сетке: включает синхронизацию всех совместимых групп; несовместимые работают автономно.
- Источник транслирует событие в группу **только через сетку** (запрещены прямые вызовы «плитка → плитка»).
- Механизм связи: существующий в проекте механизм (PyQt-сигналы, если они уже применяются между виджетами), не вводить второй.

### 9.2. Правила трансляции

- Транслируются только совместимые оси: тот же `sync_group` + та же шкала (лин/лог).
- **Пропорционально (решено)** для A/B/E: транслируются не абсолютные пределы, а фактор и якорь; каждая плитка применяет их к своим пределам — решает проблему разных диапазонов данных.
- **Абсолютная** — только для категории C с общим доменом (`ternary-100`, `tas-field`).
- Pie (D) не участвует.
- Защита от циклов: флаг «идёт трансляция» хранится в **сетке**; обработчики плиток проверяют его первым действием; пределы применяются напрямую без повторного срабатывания.

### 9.3. Нюансы

- Rect-zoom в синхронизации: применяется как фактор + якорь относительно исходных пределов источника.
- Пан в синхронизации: смещение в долях диапазона.
- Синхронная трансляция батчится: mutate all → draw all (одна отрисовка группы).

## 10. Шаг зума и настройки

- Шаг зума — **единственная настраиваемая константа взаимодействий**. Дефолт ×1.2.
- Хранится в проектном механизме настроек (том же, что «Режим алгоритма»), рядом с ним на странице «Настройки». Ключ фиксируется один раз и не размножается по модулям.
- Цепочка: плитка запрашивает шаг у сетки, сетка — у конфига. Плитка и математический модуль получают шаг **только параметром**, конфиг сами никогда не читают. Захардкодить шаг в плитке запрещено.
- Применяется мгновенно, без перезапуска, ко всем существующим плиткам при следующем событии зума; пересоздание плиток не требуется.
- При удалённом/битом значении в конфиге — откат на дефолт ×1.2, без падения.
- Спецификация типов не ограничивает шаг (все текущие типы без ограничений); сам шаг — только из глобальных настроек.

## 11. Экспорт

- Сохраняется: экспорт сохраняет фигуру в текущем состоянии (зум/пан не сбрасываются); формат из расширения (PNG/PDF/SVG).
- При синхронизированном зуме экспорт одной плитки сохраняет её вид — корректно.
- Групповой экспорт в один многостраничный PDF — **вне рамок** (возможное расширение).

## 14. Чистая математика отдельно от Qt

- Арифметика пределов (линейная, логарифмическая, пропорциональная трансляция, пан в долях диапазона, `anchor_fraction(anchor, lims)` и обратно) — в модуль без импортов PyQt и matplotlib (например, `src/gui/widgets/zoom_math.py`, финальное место — на ревью).

- `_zoom_lims` — чистая функция без состояния, покрыта юнит-тестами напрямую: линейный, логарифмический, вырождение в точку, защита `<= 0`, достижение `min_range_width`.

## 15. Требования к качеству

- **Типизация:** новые модули полностью аннотированы; `tuple[float, float]` для пределов; enum для категорий и для результата разбора модификаторов; без `Any` в новом коде.
- **Докстринги:** публичные функции на русском, с единицами и инвариантами («якорь не смещается», «фактор > 1 — приближение»).
- **Тесты:** каждый новый публичный метод — минимум один тест; матмодуль — параметризованные тесты на границы (фактор 1.0, вырождение, лог с `lo<=0`, трансляция между разными диапазонами).
- **Размер функций:** обработчики событий ≤ 15 строк логики; вычислительный код — в отдельные функции.
- **Линт:** существующие проверки проекта (ruff/flake8) проходят без предупреждений.

## 17. Валидация и тестирование

### 17.1. Автоматические (offscreen, `QT_QPA_PLATFORM=offscreen`)

Расширить `gui_full_smoke.py`:

1. Матрица: для каждой категории A–F зум меняет пределы только на разрешённых осях; запрещённые оси неподвижны (точность 1e-9).
2. Правило якоря: точка под курсором сохраняет позицию (существующая проверка сохраняется).
3. Круговая: колесо не изменяет пределы; клик по срезу (синтетическое событие) вызывает explode; повторный клик возвращает.
4. Синхронизация: две Harker с разными диапазонами — зум на одной применяет пропорциональный фактор на второй; ось Y второй не тронута при несовпадении `sync_group`.
5. Отсутствие циклов: синхронная трансляция не вызывает повторную (счётчик вызовов).
6. Групповой сброс; сброс возвращает `default_limits` для TAS-подобных.
7. Конфликт лупы: при активном zoom-tool тулбара встроенный scroll-зум не срабатывает (один зум на событие, по счётчику).
8. **Смена шага в настройках:** после изменения значения следующий зум применяет новый фактор (конфиг + один synthetic scroll event); все плитки применяют новый шаг без пересоздания.
9. Регрессия: базовый сьют не ломается; число тестов растёт.

### 17.2. Ручная проверка

Чек-лист (2–4 диаграммы, включая одну pie):
- колесо у курсора; Ctrl/Shift-комбинации; отсутствие «двойного» зума при включённой лупе;
- pie: hover с процентами, explode, «По умолчанию» возвращает форму;
- синхронизация двух Harker: зум на одной — вторая следует пропорционально;
- смена числа колонок сетки сохраняет зум и режим синхронизации;
- смена шага в настройках применяется к существующим плиткам мгновенно.

## 21. Этапность (каждый этап — отдельный коммит/PR с тестами §17)

1. **Этап 1 — инфраструктура:** реестр спецификаций, отключение встроенного scroll-зума, матрица категорий, скрытие неподдерживаемых кнопок. (Закрывает: двойной зум, зум «вслепую» для запрещённых типов.)
2. **Этап 2 — декартовы и тепловые:** перенос зума/якоря/лог-шкал в чистый модуль, модификаторы Ctrl/Shift, групповые операции сетки, шаг из настроек.
3. **Этап 3 — равноаспектные и полярные:** зум с сохранением аспекта, radar через `r`-пределы, `default_limits`.
4. **Этап 4 — круговые:** hover, explode, сброс.
5. **Этап 5 — синхронизация:** группы, пропорциональная трансляция, защита от циклов.

### Принципы реализации

- **Инкрементальность:** этап самодостаточен, сьют зелёный после каждого. Запрещены «большие взрывы» (одновременные переименование + перемещение + изменение поведения в одном коммите).
- **Инварианты публичного API:** `ChartsPage`, `OutputPage`, `build_data_from_results()`, `set_data()`, `MultiChartView.render()`, `columns`, экспорт не меняют поведение; допускается только расширение (новые методы, опциональные параметры со значениями по умолчанию).
- **Неприкосновенные гарантии:** `_release_tiles` (закрытие фигур через `plt.close`), экспорт текущего вида, сохранение зума при `_reflow_tiles`, работа под `QT_QPA_PLATFORM=offscreen`.
- **Один источник истины о типе:** все новые слои получают тип из фигуры/плитки; дублирование классификации диаграмм запрещено.
- **Приоритеты:** этот документ уточняет ТЗ; при конфликте с существующим кодом вне зоны рефакторинга — побеждает существующий код.
