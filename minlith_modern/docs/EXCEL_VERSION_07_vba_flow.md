# EXCEL_VERSION_07 — Поток управления VBA (диспетчеризация)

**Источник:** `Ispravlenny_MINLITH1_2010.xlsm` (макросы Module1-3)
**Реплика:** `src/core/excel_port/vm.py` (+ `vba_structure.json` из `vba_extractor.py`)
**Статус:** Поток воспроизведён Python-VM дословно; 231 процедура, 5 типов пород сверены с Excel.

---

## 1. Два слоя исходника

В оригинале вся **математика** живёт в ~931 формулах листов, а VBA макросы —
это **оркестрация**: они выбирают диапазоны (`Select`), копируют значения
(`Copy`/`Paste`), очищают ячейки (`Clear`) и по флагам-ячейкам вызывают
другие процедуры (`Call`). Сами макросы не считают: не содержат арифметики.

VM умеет всего 9 операций (см. `EXCEL_VERSION_00` §4):

| Операция | Что делает в VM |
|----------|-----------------|
| `Sheets` | переключить активный лист |
| `Goto`/`Select` | выделить диапазон (A1 или R1C1, с префиксом листа) |
| `Copy` | прочитать значения выделенного → буфер |
| `Paste` | записать буфер в выделенное (`xlNone`/`xlMultiply`) |
| `Clear` | обнулить выделенное |
| `Formula` | записать константу в ячейку |
| `If Range` | ветвление по значению ячейки-флага (≠0 → True) |
| `Call` | вызвать другую процедуру |
| `other` | прочие строки VBA (операции вывода игнорируются) |

## 2. Верхний уровень: `aDefin`

`aDefin` (31 операция) — **единственная точка входа**. Что делает:
1. чистит рабочие диапазоны на листах `Нач+Type 3` и `Нач+Type 12`
   (`al3_1`, `al4_1`, `mg0`, `ca_n`, `si_n`, `ab`, `al_1`);
2. переключается на `Нач+Type 3` и вызывает **`ca_1`**.

Схема:
```
aDefin
 └─ ca_1
     ├─ [flag E9 = ИСТИНА] → ca_t   (основная ветка)
     └─ [else]             → ca_e   (ветка при E9 = ЛОЖЬ)
         ├── ca_t → u0
         └── ca_e → u0
```

`E9` — булев флаг («образец валиден»); у семи эталонных образцов
Е9 = ИСТИНА у шести, у T-O2 — ЛОЖЬ (при этом T-O2 корректно считается
через `ca_e`). `ca_t` копирует флаг расчёта и вызывает **`u0`**; `ca_e`
делает то же самое по своей ветке. Обе сходятся на `u0`.

## 3. Каскад `u_*` и `v_*` — путь по типам

`u0` запускает цепочку переключателей `u_1..u_10`, которые циклически
вызывают **`v_1`** (составление набора процедур для типа).

```
u0 → u_1 → v_1 → aType_1 → v_11 → aType_1 → v_12 → aType_2 → v_13 → aType_3 → v_14 → aType_4 + aType_5
```

Ключевой механизм: **все** `aType_N` вызываются по очереди (диспетчер
`v_1..v_14` безусловно проходит всю лестницу), но каждый `aType_N` внутри
начинается с `If Range` по флагу **своего** типа. Если тип породы не
совпадает — тело процедуры пропускается.

Процедуры типа (окончательный расчёт минералов):

| Тип | Действующая процедура | Цепочка (из call_log) |
|-----|----------------------|------------------------|
| 1 (аркоз) | `aType_1` | `t_49 → t_51 → t_52an → t_53an → rVI` |
| 2 (гранит) | `aType_2` | `s_177 → s_190 → s_192(t) → s_204 → s_208 → s_213(t)` |
| 3 (базальт) | `aType_3` | `p_51 → p_61(t) → p_76 → p_90 → p_93(t) → p_97 → p_106..p_132→p_136 → p_81(e)` |
| 4 (кварцит) | `aType_4` | `m_274 → m_385 → m_401 → m_408..m_414 → m_433 → m_435t → m_437(t) → m_448 → rVI` |
| 5 (высокоглиноз.) | `aType_5` | `m_528 → m_531(w) → m_538..m_551 → m_281 → m_296(t) → m_302(t) → m_308 → m_334(t) → m_343 → rVI` |

Префиксы имён процедур соответствуют типу:
`t_*` — Type 1, `s_*` — Type 2, `p_*` — Type 3, `m_*` — Types 4/5.
Суффикс `t`/`e`/`an`/`w` — вариации ветки процедуры.

## 4. Стадии вычислений (что делают процедуры)

```
Набл. сост. → [Stage 0] → [расчёт минералов типа N] → [rVI] → [s_* / aut_2 / aut_3] → вывод
```

1. **Stage 0** (формулы листов, см. `EXCEL_VERSION_01`): ф.е., F, A,
   коэффициенты хлорита, классификация типа. Макросы `u_0..u_10` лишь
   копируют выбранные коэффициенты в расчётные ячейки.
2. **Расчёт минералов**: каждая `p_*`/`s_*`/`t_*`/`m_*` копирует
   коэффициенты и формулы строк нижней таблицы (строки 149-287), которые
   на самом деле считают минеральные нормы из ф.е.
3. **`rVI`** — «стадия VI»: нормировка минералов (%).
4. **`aut_2`, `aut_3`** — пост-обработка (пересчёт на 100%, запись вывода).
5. Итог — строки 287 (минералы) и 164-172 (анализ точности).

Куда пишется результат:
- `Нач+Type 12!A287..G287` — минеральные % (An, Pl, Fsp, Q, Chl, Ill, аморф)
- `Нач+Type 12!B164:B172` — диагностика (дефект, отсечки)
- Именованные ячейки (`q`, `ab`, `an`, `ill`, ...) — те же значения

## 6. Почему VM «просто работает»

- Ветвление по **значению ячейки** (`If Range`), а не по переменной VBA:
  VM читает флаг прямо из листа через `eval_cell`.
- `Paste` с `xlMultiply` (встречается при поправках):
  VM умножает текущее значение на вставленное.
- Ссылки вида `'Нач+Type 12'!R305C3` (префикс листа + R1C1) разрешаются
  `_resolve_ref`.
- Процедуры, которых нет в структуре (например, `clean_3`), пропускаются
  с пометкой `?name` в `call_log` — как и делает Excel (`On Error Resume Next`).
