# EXCEL_VERSION_06 — Округления (ROUND) и их влияние

**Задача раздела:** описать все места `ROUND` в оригинальной книге, как они
воспроизводятся Python-VM, и измерить их влияние на результат
(сравнение «с округлениями» и «чистый float64» — Фаза 4).

> В Excel результаты — суть образца в ф.е. (weight% × 10000 / Mw). ROUND
> используется в двух ролях: (1) **конвертация** входных вес.% в ф.е. и
> (2) **дистрибуция** — округление промежуточных минералов и нормировок
> при выводе. Роль (1) физически необходима: она воспроизводит «табличный»
> химизм исходного анализа. Роль (2) — артефакт редактора книги и даёт
> едва заметные расхождения.

## 2. Реализация: точное совпадение с Excel

Excel округляет «half away from 0» (числа вида 0.145 → 0.15). Наивный
double `round()` в Python — «banker’s», а float-представление 0.145
меньше 0.145, поэтому давал 0.14. В `excel_port`:

```python
from decimal import Decimal, ROUND_HALF_UP

def xround(value, nd=0):
    if not nd and abs(value) < 0.5:
        return 0.0
    return float(Decimal(repr(value)).quantize(
        Decimal(f"1E{int(-nd)}"), rounding=ROUND_HALF_UP))
```

Ключевые моменты:
- `Decimal(repr(value))` — аккуратная передача double без float-шума;
- `ROUND_HALF_UP` — «half away from 0», ровно как Excel;
- особый случай `abs(v)<0.5` при `nd=0` — Excel даёт 0 для ±0.49…;
- знак сохраняется при «half away from 0».

> Проверка граничного случая: `xround(0.145, 2)` == 0.15 (Excel), а
> Python float.round → 0.15? — нет: 0.14; это была реальная ошибка ГТ-кварцита
> (расхождение 0.01 в строке 287, строка «An»), исправленно в коммите `084518f`.

## 3. Чистый режим (без округлений) и его смысл

Для «истинных» значений задан второй путь вычисления:

| Компонент | Значение при `rounding=False` |
|-----------|-------------------------------|
| `xround` | `identity_round(v, nd) → v` (тождество) |
| `FormulaEvaluator(round_fn=identity)` | ROUND не округляет |
| `Workbook(round_fn=identity)` | весь граф в float64 |
| `run_sample(rounding=False)` | чистая модель без ROUND |

Это позволяет: (1) измерить вклад округлений (Фаза 4), (2) служить
эталоном для `clean_engine` (Фаза 3), (3) отделить «смысловые»
округления (вход, классификация) от «шумовых» (нормировки вывода).

## 4. Измеренное влияние (сводка по образцам)

Параметр сравнения: `abs(полный float64 − excel_port)`, максимум по именованным
переменным (в ф.е.) и по вес.% (строки 287):

| Образец | тип | дифф-переменных | макс|d| (ф.е.) | макс|d| вес.% | кол. строк 287 с d≠0 |
|---------|-----|-----------------|-----------------|--------|----------------------|
| BK-1 | 1 | 17 | 0.4591 (ca_n) | < 0.01 | 0 |
| Аркоз | 1 | 17 | 0.5223 (ca) | < 0.01 | 0 |
| Гранит | 2 | 22 | 0.5571 (ca) | < 0.01 | 0 |
| Базальт | 3 | 27 | 2.283 (cc) | ~0.02 | 1 (An) |
| Кварцит | 4 | 30 | 3.081 (si_n) | ~0.02 | 1 (An) |
| High-al | 5 | 34 | 0.6806 (ca) | < 0.01 | 0 |
| T-O2 | 3 | 29 | 1.691 (si_n) | ~0.02 | 1 (An) |

Наблюдения:
- Наибольшие диффы — в больших ф.е. (si_n, cc) из-за нормировочных ROUND;
  в вес.% итога это 0.01-0.02 п.п. (одна строка «An», случай 0.145/0.15).
- Знаменатель итога округляется 2 раза (D152, D154) → малые системные
  сдвиги всей суммы, порядка 10⁻² вес.%.
- При «rounding=False» образцы типов 1-2 сходятся в 287 уже без нулевого
  диффа; типы 3-5 — с +−0.01-0.02 п.п.

## 5. Вывод для clean_engine

- **Вход** (строки 2-19) и **классификация** (24-26): округление сохраняем —
  оно определяет сам тип образца.
- **Промежуточные минералы** (C214/C215/C62/C99/C102): сохраняем как есть —
  они влияют на соседние формулы (цепочки `ill→or→si_n`).
- **Нормировки** (149-153, 287): в чистом движке выполняем в float64 c
  финальным `round(2)` для вывода; сравнение «с/без ROUND» оформлено как
  функция качества.
- Public API чистой модели не обязан воспроизводить ROUND-артефакты
  (это документально зафиксировано в этом разделе).
