## 21. `src/database/repository.py`

### BUG 38 — `repository.py:45` — Type confusion: `_session_factory` can be a Session instance or callable
```python
def __init__(self, session: Session | None = None) -> None:
    self._session_factory = session or get_session
```
If a `Session` object is passed, `_session_factory` is a `Session` instance. The `_session()` method (line 47-50) checks `if callable(self._session_factory)`. A `Session` instance is **callable** in SQLAlchemy (it acts as a context manager and session factory in some versions), so `callable()` returns `True`, causing `self._session_factory()` to be called on the Session instance, which would attempt to **call** the Session as a function. This would likely create a new Session via `__call__` if supported, or raise `TypeError`. The type annotation says `session: Session | None` but the logic treats it as a sessionmaker/factory. This is a **type mismatch**.

### BUG 39 — `repository.py:128` — `.get()` is deprecated in SQLAlchemy 2.0
```python
db_sample = session.query(SampleDB).get(sample_id)
```
`Query.get()` is deprecated in SQLAlchemy 2.0. The recommended replacement is `session.get(SampleDB, sample_id)`. Same issue on line 144. This will generate deprecation warnings and may break in future SQLAlchemy versions.

### BUG 40 — `repository.py:142-146` — `delete_sample` accepts `int` but is called with `str` from history_page
As noted in BUG 25, `delete_sample(sample_id: int)` is called with a string sample name from `history_page.py:123`. The `session.query(SampleDB).get(sample_id)` with a string will not match any integer primary key, so the deletion silently does nothing. This is a **cross-file type mismatch**.

### BUG 41 — `repository.py:194-196` — Potential empty `in_()` clause
```python
old_calcs = session.query(CalculationDB).filter(
    ~CalculationDB.id.in_(keep_ids)
).all()
```
If `keep_ids` is empty (e.g., no calculations exist), `CalculationDB.id.in_([])` generates `WHERE id IN ()` which is invalid SQL in some databases. SQLite handles this gracefully (returns empty result), so it works in practice.
