## 1. КАК РАБОТАТЬ С ЭТИМ ДОКУМЕНТОМ

### 1.1. Назначение

Этот файл — **дорожная карта реализации**. Он:
- Разбивает ТЗ на конкретные этапы
- Определяет контрольные точки (что должно работать перед переходом дальше)
- Фиксирует зависимости между этапами
- Служит чек-листом для проверки готовности

### 1.2. Принцип работы

```
Этап N → Код → Тесты → Проверка → Утверждение → Этап N+1
              ↑___________________________↓
                    (если не утверждено — возврат)
```

**Правило:** Не начинать этап N+1, пока этап N не утверждён.

### 1.3. Формат этапа

Каждый этап содержит:
- **Цель** — что должно быть сделано
- **Вход** — что нужно иметь перед началом
- **Выход** — что должно работать
- **Контрольные точки** — список проверок
- **Файлы** — что создаём/изменяем
- **Риски** — что может пойти не так
- **Время** — оценка трудоёмкости

### ЭТАП 1: Модели данных и константы

**Цель:** Создать типизированную основу для всего проекта.

**Вход:** Утверждённое ТЗ, оригинальный файл MINLITH1.xlsx.

**Выход:**
- Все dataclasses для данных
- Константы (молярные массы, формульные веса)
- Справочники алиасов оксидов
- Enum для типов пород

**Контрольные точки:**
- [ ] `OxideComposition` создаётся из словаря `{"SiO2": 52.31, ...}`
- [ ] `MineralWeights` содержит все 24 минерала
- [ ] `RockType` enum имеет 5 значений с корректными условиями
- [ ] Алиасы оксидов распознают "SiO₂", "SiO 2", "Кремнезём"
- [ ] Переключение IUPAC ↔ MINLITH меняет молярные массы
- [ ] Все dataclasses — frozen (immutable)

**Файлы:**
```
src/core/models.py       # Все dataclasses
src/core/constants.py    # Константы, справочники
```

**Риски:**
- Неправильная молярная масса TiO₂ в оригинале — уточнить из файла
- Несоответствие формульных весов — проверить по оригиналу

**Время:** 1 день

**Критерий утверждения:** Код компилируется, тесты создания объектов проходят.

### ЭТАП 2: Алгоритм Type 1-5

**Цель:** Переписать 500+ строк Excel-логики на чистый Python.

**Вход:** Этап 1 (модели), оригинальный файл MINLITH1.xlsx.

**Выход:**

- Функция `_stage_0` (подготовка данных)
- Каждая функция принимает `FormulaUnits`, возвращает `MineralComposition`

**Контрольные точки:**
- [ ] Этап 0: перевод в ф.е. даёт те же значения, что в оригинале (БК-1, T-O2)
- [ ] Коэффициенты k1-k4 для F=0.696 совпадают с оригиналом
- [ ] Тип 1: результат для T-O2 совпадает с оригиналом ±0.01%
- [ ] Тип 2: протестирован на синтетических данных
- [ ] Тип 3: протестирован на БК-1
- [ ] Тип 4: протестирован на синтетических данных
- [ ] Тип 5: протестирован на синтетических данных
- [ ] Этап VI: распределение Ca, Mg, Fe совпадает с оригиналом
- [ ] Debug trace собирает все промежуточные переменные

**Файлы:**
```
src/core/types_logic.py      # Type 1-5 branching
src/core/coefficients.py     # k1-k4 adaptive
src/core/debug_tracer.py     # Trace collector
```

**Риски:**
- Сложность воспроизведения goto-логики Excel
- Ошибки в ручном переносе формул
- Несоответствие округления (Excel ROUND vs Python round)

**Время:** 3-5 дней

**Критерий утверждения:** Расчёт T-O2 даёт те же минералы ±0.01%, debug trace проходит все шаги.
