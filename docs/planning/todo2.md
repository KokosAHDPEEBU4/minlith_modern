## 1. Контекст

Проект MINLITH Modern (`minlith_modern/`) — Python-реализация нормативного
минералогического расчёта. Изначально был написан `TheoryAlgorithm` «по теории»
(файлы 00-07, см. `docs/algorithm/`). При сверке с оригиналом выяснилось, что теория
НЕ воспроизводит оригинальный MINLITH (расхождения принципиальные: хлорит,
каолинит, иллит распределяются иначе).

Появился оригинальный файл с макросами: `Ispravlenny_MINLITH1_2010.xlsm`.
При разборе выяснилось: VBA-макросы (231 Sub) — это НЕ арифметика, а «поток
управления», копирующий значения ячеек в именованные диапазоны. Вся математика —
в ~930 формулах листов `Нач+Type 12` (типы 1-2) и `Нач+Type 3` (типы 3-5),
ссылающихся на ~95 именованных диапазонов-«переменных».

## 5. ПОДРОБНЫЙ ПЛАН ПО ФАЗАМ

### Фаза 1 — полное декодирование ФОРМУЛ (по решению «сначала формулы»)

#### Шаг 1.1. Извлечение и аудит данных (data-driven)

- Скрипт (openpyxl) читает `Ispravlenny_MINLITH1_2010.xlsm` и выгружает в JSON
  (`src/core/excel_port/data/`):
  - все формулы ячеек листов `Нач+Type 12` и `Нач+Type 3`;
  - карту именованных диапазонов → лист/ячейка;
  - список Subs и их действий (парсинг VBA) → граф вызовов.
- JSON коммитим — порт работает без Excel.
- Аудит: какие функции Excel реально встречаются (ROUND, IF, AND, OR, MIN/MAX,
  INT, ABS, ...); какие стили ссылок (A1/R1C1/имена/межлистовые); есть ли
  циклические ссылки.
- **Выход:** `docs/../../minlith_modern/docs/EXCEL_VERSION_00_overview.md` — карта листов, словарь
  переменных, аудит функций/ссылок.

**Факты об оригинале (для аудита):**
- `Нач+Type 12`: ~418 формул; строки: стадия 0/подготовка 1-42, типы 1-2 44-263,
  стадия VI 92-140, вес.% 143-171, итог 286-352.
- `Нач+Type 3`: ~513 формул; строки: подготовка 1-42, типы 3-5 44-556.
- Именованных диапазонов ~95: `al_1..al_4`, `si_1..si_4`, `fe3_1/fe3_2`,
  `fe4_2`, `mg`, `k`, `na`, `ca`, `ab`, `an`, `ill`, `chl`, `or`, `q`, `dl`,
  `cc`, `ank`, `srp`, `kn`, `gb`, `mm`, `prl`, `ht`, `rch`, `sd`, `mst`,
  `k_1..k_4`, `ca_n/mg_n/fe_n/si_n`, `al3_1..`, `si3_1..`, `al4_1..`,
  `si4_1..`, `mg0/mg_1`, `fe_1`, `pr0`, `so`, `cl`, `s`, `f`, `c0`.

#### Шаг 1.2. Декодирование формул по блокам (полностью)

Последовательно разобрать ВСЕ формулы каждого блока, задокументировать каждую в
MD, затем реализовать в интерпретаторе.

Блоки листа `Нач+Type 12`:
1. **Стадия 0 / подготовка** (строки 1-42): ф.е. оксидов, коррекции
   (CaO−апатит/F/Na, FeO=Fe₂O₃·0.9+FeO), F, A, k1-k4 по диапазонам F
   (колонки G-L), булевы флаги F20-F26 классификации.
2. **Тип 1** (ветки 1.x: 44-90).
3. **Тип 2** (ветки 2.x: 172-283).
4. **Стадия VI** (92-140): Ca_n/Mg_n/Fe_n/Si_n, ветки VI A/Б/В, Dl/Ank/Cc/Rch/
   Sd/Srp/Mst/Ht/Prl, условие `Ca_n<=250`.
5. **Вес.% и нормировка** (143-171): ф.е.→вес.%, D151 сумма, D154, E153..
   нормировка, дефект (164-171).
6. **Итоговая таблица** (286-352): строка 287 = результат образца.

Блоки листа `Нач+Type 3`:
7. **Подготовка** (1-42): свои коэффициенты/флаги для типов 3-5.
8. **Тип 3** (44-~250, ветки 3.x и под-ветки 33xxx).
9. **Тип 4** (~270-430).
10. **Тип 5** (~520-556).
11. **Межлистовые связи**: какие формулы Type 3 ссылаются на Type 12 и наоборот.

Каждый блок → раздел MD + реализация в интерпретаторе. Формат MD: таблицы
«переменная → формула Excel → смысл → влияет на → порядок», псевдокод.

#### Шаг 1.3. Мини-интерпретатор Excel-семантики

- AST-парсер + оценщик: арифметика, сравнения, `IF`, `AND`, `OR`, `TRUE/FALSE`,
  `ROUND(x,n)` с семантикой Excel (half-away-from-zero — своя `xround`,
  НЕ Python `round`), ссылки A1/R1C1/имена/межлистовые.
- Выполнение в порядке зависимостей с кэшем; детект циклов.

#### Шаг 1.4. Эталонная сверка формул с Excel

- Через Excel COM (pywin32) пересчитать оригинал для БК-1 и T-O2, снять значения
  ВСЕХ ячеек/переменных.
- Тест: интерпретатор == Excel по каждой формуле/переменной.
- **Важно:** на этом шаге VM ещё нет — сверяем именно оценку формул: берём
  значения переменных из Excel и проверяем, что оценка каждой формулы совпадает.

**Критерий готовности Фазы 1:** все формулы обоих листов декодированы,
реализованы и задокументированы; оценка формул совпадает с Excel на БК-1 и T-O2.

### Фаза 2 (часть 1) — VBA-порт (после формул)

#### Шаг 2.1. Разбор VBA → таблица переходов

- Автоматически разобрать 231 Sub:
  - `If Range("d97")=True Then Call X Else Y` → ветвление;
  - `copy RxCx → paste имя` → присваивание `имя := value(RxCx)`;
  - переносы блоков между листами (`A1:F19` из Type 3 в Type 12);
  - `ClearContents` — сброс ячеек;
  - `PasteSpecial Operation:=xlMultiply` — **умножение диапазона k**, НЕ
    присваивание;
  - вставка строк (`aut_2`).
- Сохранить граф вызовов в JSON.

#### Шаг 2.2. VM

- VM = словарь переменных + операции копирования/присваивания/ветвления.
- Исполнение полного цикла: вход → подготовка (`aDefin`, `u_*`, `ca_*`) →
  классификация (`v_*`) → ветки типа (`aType_*` → `m_/p_/s_`) → стадия VI
  (`rVI`) → сборка вывода (`aut_2/aut_3`).
- Результат: значения всех переменных + финальные минералы.

#### Шаг 2.3. Сверка VM с Excel

- БК-1 и T-O2: совпадение по **всем** переменным (допуск 0.01 ф.е.).
- Дополнить MD (`../../minlith_modern/docs/EXCEL_VERSION_07_vba_flow.md`).

**Критерий готовности Фазы 2:** `excel_port` полностью воспроизводит Excel на
БК-1 и T-O2 по всем переменным.
