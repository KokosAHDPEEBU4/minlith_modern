# Разобранный числовой пример (на составе T-O2 из вашего README)

Беру ровно тот состав, что уже есть в вашем README как пример Python API:

```
SiO2=52.5, Al2O3=23.41, Fe2O3=1.71, FeO=8.06, MgO=2.35, CaO=0.28, Na2O=0.94, K2O=3.45
```

Сумма оксидов = 92.7 вес.% (это нормально — не хватает LOI/H₂O, о чём отдельно в файле `07`). Считаю по правилам из файлов 01-03 **буквально, шаг за шагом**, чтобы вы могли свериться построчно со своей реализацией. Это не "официальный" ответ MINLITH (я не знаю, что выдаст оригинал для этого состава) — это иллюстрация механики баланса и, что важнее, **демонстрация двух реальных проблем**, которые всплывают на живых данных и требуют решения на уровне архитектуры, а не только формул.

## Шаг 0. Моли

| Оксид | вес.% | M | моли |
|---|---|---|---|
| SiO₂ | 52.5 | 60.08 | 0.87383 |
| Al₂O₃ | 23.41 | 101.96 | 0.22960 |
| Fe₂O₃ | 1.71 | 159.69 | 0.01071 |
| FeO | 8.06 | 71.85 | 0.11218 |
| MgO | 2.35 | 40.30 | 0.05831 |
| CaO | 0.28 | 56.08 | 0.00499 |
| Na₂O | 0.94 | 61.98 | 0.01517 |
| K₂O | 3.45 | 94.20 | 0.03662 |

P₂O₅, S, SO₃, F, Cl, CO₂, TiO₂, MnO — в этом примере отсутствуют (считаем 0) → вся стадия 1 (файл `01`) даёт нули, остаточные пулы = исходным молям.

## Классификация типа (по индикатору из файла 02)

```
R = Al2O3 / (Na2O + K2O + CaO) = 0.22960 / (0.01517+0.03662+0.00499)
  = 0.22960 / 0.05678 ≈ 4.04
```

Высокое R → тип с существенным избытком Al₂O₃ над щелочами (условный "тип 4" из таблицы файла 02: глины/аргиллиты, доминирование иллита/каолинита). Это разумно для состава с 23.4% Al₂O₃ при почти отсутствующем CaO.

## Стадия 2 — полевые шпаты (наивный порядок Or → Ab → An)

```
Or:  n = min(K2O, Al2O3) = min(0.03662, 0.22960) = 0.03662
     Al2O3_ост = 0.22960 - 0.03662 = 0.19298
     K2O_ост   = 0
     SiO2_ост  = 0.87383 - 6*0.03662 = 0.65396

Ab:  n = min(Na2O, Al2O3_ост) = min(0.01517, 0.19298) = 0.01517
     Al2O3_ост = 0.19298 - 0.01517 = 0.17781
     Na2O_ост  = 0
     SiO2_ост  = 0.65396 - 6*0.01517 = 0.56296

An:  n = min(CaO, Al2O3_ост) = min(0.00499, 0.17781) = 0.00499
     Al2O3_ост = 0.17781 - 0.00499 = 0.17282
     CaO_ост   = 0
     SiO2_ост  = 0.56296 - 2*0.00499 = 0.55297
```

## ⚠️ Проблема №1: иллиту не хватило калия

Иллит по нашей схеме (файл 02) считается как `min(K2O_ост, Al2O3_ост/3)`. Но K₂O_ост уже **обнулился на шаге ортоклаза** — весь калий "съеден" ортоклазом раньше, чем дошла очередь до слюды. В итоге:

```
Ilt: n = min(0, 0.17282/3) = 0     ← иллита не будет вообще
```

Весь оставшийся Al₂O₃ (0.17282 моль) уйдёт в каолинит:

```
Kln: n = 0.17282
     Al2O3_ост = 0
     SiO2_ост  = 0.55297 - 2*0.17282 = 0.20733
```

**Это и есть та самая точка, где "наивный" порядок даёт физически правдоподобный, но, скорее всего, не совсем корректный результат.** Реальные глинистые породы почти всегда содержат и иллит, и полевой шпат одновременно — весь K₂O редко уходит целиком в один минерал. Именно здесь нужен k-коэффициент (`k_or`, доля K₂O, идущая в ортоклаз, а не в иллит) — например, если эмпирически известно, что для пород такого типа (высокое R) в среднем 60% K уходит в иллит и только 40% в КПШ, порядок должен быть:

```
K2O_to_or  = k_or * n(K2O)          # напр. k_or = 0.4
K2O_to_ilt = (1 - k_or) * n(K2O)    # напр. 0.6
```

и оба минерала считаются параллельно от разных долей одного и того же исходного K₂O, а не последовательно "кто раньше встал". **Это главный практический вывод примера**: для катионов, которые реально делятся между несколькими минералами одновременно (K между Or/Ilt, Na между Ab/цеолитами, Fe между силикатами/оксидами/карбонатами), последовательная схема "первый пришедший всё забирает" — грубое приближение. Правильная архитектура — считать такие развилки как **долевое распределение с коэффициентом, зависящим от типа породы**, а не как жёсткий приоритет.

## Стадия 3

```
Магнетит: n = min(FeO, Fe2O3) = min(0.11218, 0.01071) = 0.01071
          FeO_ост   = 0.11218 - 0.01071 = 0.10147
          Fe2O3_ост = 0

Кварц:    n = SiO2_ост = 0.20733   (положительный — хороший знак, ошибок в порядке нет)
```

## ⚠️ Проблема №2: MgO и остаточный FeO некуда деть

После всех шагов остаются:
```
FeO_ост = 0.10147 моль  (≈ 7.29 вес.%)
MgO_ост = 0.05831 моль  (≈ 2.35 вес.%, вообще не тронут ни на одном шаге)
```

В наборе минералов из файлов 01-03 **нет минерала, который заберёт Fe/Mg, когда свободного Al₂O₃ уже не осталось** (хлорит из файла 02 требует Al₂O�3, а он весь ушёл в каолинит). В реальной осадочной породе это, скорее всего, означает, что в составе должен присутствовать **биотит, глауконит или Fe-Mg силикат без алюминия** (например, серпентиноподобный минерал, или просто более сложная схема, где часть Al₂O₃ изначально резервируется под хлорит/биотит до каолинита, а не после).

**Практический вывод**: список минералов из файла 02 неполный для составов с высоким Fe+Mg и одновременно высоким Al (частая ситуация для глауконитовых песчаников, богатых железом глин, некоторых сланцев). Нужно добавить хотя бы один "аварийный сток" для Fe/Mg — см. файл `07`, раздел про дополнительные минералы.

## Итог по этому примеру (с учётом обеих оговорок)

| Минерал | моли | масса (условно, вес.%) |
|---|---|---|
| Ортоклаз | 0.03662 | 20.38 |
| Альбит | 0.01517 | 7.95 |
| Анортит | 0.00499 | 1.39 |
| Каолинит* | 0.17282 | 44.61* |
| Магнетит | 0.01071 | 2.48 |
| Кварц | 0.20733 | 12.45 |
| **не пристроено (FeO+MgO)** | — | **9.64** |

\* Масса каолинита включает "добавленную" конституционную воду (2·H₂O на формулу), которой не было в исходном анализе — см. следующий файл, это не ошибка баланса, а нормальное следствие того, что глинистые минералы гидратированы, а сам анализ (в этом примере) LOI/H₂O не содержит.

Сумма минералов (89.29) + непристроенное (9.64) = 98.93, что близко (в пределах ожидаемого расхождения от округлений и от отсутствия LOI) к сумме "исходные оксиды (92.7) + добавленная конституционная вода каолинита (6.23)" = 98.93 — то есть **баланс массы сходится ровно так, как и должен**, просто у вас на выходе появляется вода, которой не было на входе, и остаётся Fe/Mg, для которого нет минерала-приёмника. Оба момента — не баги, а закономерные последствия неполноты набора минералов/входных данных, которые нужно закрыть на уровне архитектуры (см. файл 07).
