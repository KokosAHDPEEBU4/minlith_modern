# Граф разветвлений — руководство пользователя

Как пользоваться страницей **«Граф»**: посмотреть, по каким ветвям алгоритма
пошёл образец, и вручную выбрать ветку с пересчётом.

> Техническая база: `docs/planning/TZ_BRANCH_GRAPH.md`,
> `docs/planning/BRANCH_GRAPH_SELECTION.md`.

## Где находится

Сайдбар → **«Граф»** (страница `BranchGraphPage`). Список образцов заполняется
автоматически после расчёта (одиночного или пакетного). Выберите образец в
выпадающем списке сверху.

## Что показывает

Дерево решений алгоритма `excel_parity`:

- **Стадия 0** — полоса коэффициентов хлорита (`H5/J5/L5/H12/J12/L12`) и тип
  породы (1–5);
- **Решения типа** — внутренние развилки типов 1, 2, 3, 4–5;
- **Этап VI** — распределение Ca/Mg/Fe/Mn (`A/B/C-srp/C-mst/C-mst2`).

Обозначения:

| Метка | Значение |
|---|---|
| **✓** | ветка, по которой пошёл образец (жирный шрифт) |
| **★** | ветка, выбранная пользователем вручную (override) |
| без метки | ветка не пройдена |

Для каждой ветки показаны условие и источник в Excel (ячейка/флаг/процедура).

## Как выбрать ветку и пересчитать

1. Выберите **образец** в списке.
2. Выберите **ветку** (дочернюю строку, а не заголовок решения) — кнопка
   «Принудительно выбрать ветку» станет активной.
3. Нажмите **«Принудительно выбрать ветку»** — решение попадёт в список
   override (виден справа).
4. Нажмите **«Пересчитать с выбранными ветками»** — образец считается заново;
   выбранные ветки в дереве помечаются ★.
5. **«Снять выбор ветки»** — сбросить все принудительные ветки (возврат к авто).

Можно задать несколько решений сразу (например, полосу и тип). Override хранится
в `CalculationConfig.branch_overrides` (`{decision_id: branch_id}`).

## Экспорт и сравнение

- **«Экспорт маршрута (JSON)»** — сохранить траекторию решений образца в файл.
- **«Сравнить с авто»** — показать отличия авто-маршрута от принудительного.
- **«Сохранить сценарий…»** — сохранить текущий набор принудительных веток в
  JSON (`{"branch_overrides": {...}}`).
- **«Загрузить сценарий…»** — применить сохранённый набор веток (проверяется по
  каталогу; недопустимые — отклоняются с сообщением).

Пакетный отчёт по сравнению движков (все образцы сразу) — в диалоге
**«Сравнить движки»** на странице «Результаты», кнопка
**«Экспорт отчёта (CSV, все образцы)»**.

## Какие решения можно переопределять

Все переопределяемые решения имеют в каталоге признак `overridable=True`
(`src/core/excel_parity/branch_catalog.py`):

- стадия 0: `coefficient_band`, `rock_type`, `stage_vi`;
- тип 1: `type1.t_49`, `type1.t_73`;
- тип 2: `type2.an`, `type2.s204`, `type2.ill_or`, `type2.fe_ill`;
- тип 3: `type3.d61`, `type3.d162`, `type3.d180`, `type3.d188`, `type3.d200`,
  `type3.p_114`, `type3.p_142`, `type3.p_53`, `type3.p_97`;
- тип 4–5: `type45.d334`, `type45.d346`, `type45.d287`, `type45.d302`,
  `type45.d322`, `type45.d294`, `type45.d308`, `type45.d317`, `type45.d418`.

Остальные (сгруппированные) записи — заглушки `overridable=False` и в дереве
не выбираются.

## Ограничения и нюансы

- Выбор ветки — **эксперимент**: формулы выбранной ветки применяются даже если
  исходные остатки для неё не предназначены (значения могут быть «шумными»).
  Это ожидаемо.
- Поведение **по умолчанию не меняется**: без override расчёт идентичен
  обычному (паритет с Excel сохранён).
- `CalculationResult.rock_type` — классификация калькулятора, а не движка:
  при принудительном типе она может не совпасть с выбранной веткой, но состав
  минералов и маршрут считаются по выбранной ветке.
- **«Сравнить движки»** (страница «Результаты») — отдельная функция: сравнивает
  `excel_parity` и `excel_exact` по минералам (ф.е.) с диаграммой |Δ|; к выбору
  ветвей отношения не имеет.
