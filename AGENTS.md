# AGENTS.md

Памятка для ИИ-агентов и разработчиков, работающих в репозитории `Lene`.

## Обязательное правило: документация не отстаёт от кода

**Любое изменение кода или поведения** (новый функционал, исправление, изменение
алгоритма, экспорта, диаграмм, настроек) **должно сопровождаться обновлением
соответствующих md-файлов в том же запросе/коммите**:

- `minlith_modern/README.md` — возможно, «что умеет продукт» (диаграммы, экспорт, GUI)
- `minlith_modern/CHANGELOG.md` — добавлять записи в раздел `[Unreleased]`
- `minlith_modern/WORKFLOW.md` — тестовые команды, структура, ключевые паттерны; **счётчики тестов сверять с реальным прогоном `pytest`**
- `docs/planning/todo2.md` — статусы паритета/портов
- `docs/reference/API_REFERENCE.md` — публичный API; **поле «Статус» (версия) сверять с актуальной версией приложения**
- индексы: `README.md` (корень), `docs/README.md` — при добавлении/переносе файлов

Числа в документации (количество тестов, диаграмм, версии) брать из фактического
состояния кода (`git log`, `pytest`, инвентаризация `BUILTIN_CHARTS`), а не из памяти.

## Как работаем с файлами

- Перемещение/удаление отслеживаемых файлов — через **`git mv`** (сохраняем историю).
- **Ничего не удалять окончательно**: неиспользуемое/дубликаты переносить в `_trash/`
  (или `_trash/minlith_modern/`). Корзину чистит сам пользователь.
- Русские имена файлов (`src_excel/`, `pdf/`) двигать через Python-скрипты
  (Windows-консоль коверкает кодировку).
- Внутренние ссылки между md-файлами — относительные пути (`../reference/…`); при переносе
  файла обновлять ссылки на него во всех md, где он упомянут.
- Исходники, с которых сделаны переносы (xlsm и пр.) — только в `src_excel/`, в коде не используются.
